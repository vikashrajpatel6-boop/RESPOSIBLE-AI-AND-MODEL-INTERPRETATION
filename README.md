# Responsible AI: Model Explainability, Bias Detection, and Fairness Analysis

**Alfido Tech AI/ML Internship — Task 4**

## Overview
This beginner-friendly project trains a Logistic Regression model on the UCI Adult Census Income dataset, evaluates its performance, measures permutation feature importance, uses SHAP for global/local explanations, and compares outcomes across recorded sex, race, and age groups.

## Objectives
- Understand model performance using accuracy, precision, recall, F1-score, ROC-AUC, and a confusion matrix.
- Identify useful input features with permutation importance.
- Explain global and individual model outputs with SHAP when the environment supports it.
- Compare positive prediction rates and error rates across groups.
- Recommend practical, evidence-based fairness checks and mitigation steps.

## Dataset
UCI Machine Learning Repository — Adult dataset: https://archive.ics.uci.edu/dataset/2/adult  
Target: income (`>50K` versus `<=50K`). Sensitive/group attributes used for analysis: `sex`, `race`, and age bands. The notebook inspects the data after loading; it does not invent results.

**Important:** this is a historical teaching dataset, not a validated tool for real employment, credit, or other high-impact decisions.

## Methods
- Preprocessing: median imputation and scaling for numerical fields; most-frequent imputation and one-hot encoding for categorical fields.
- Model: Logistic Regression, fitted with a scikit-learn pipeline.
- Evaluation: accuracy, precision, recall, F1-score, ROC-AUC, classification report, confusion matrix.
- Feature importance: permutation importance on held-out data.
- Explainability: SHAP KernelExplainer, with a small sample to control runtime.
- Fairness: group sizes, positive prediction rates, accuracy, precision, recall, false-positive rates, and false-negative rates by sex, race, and broad age group.

## Mitigation recommendations
Investigate group-level error differences, improve representation and data quality, review historical labels and proxy features, compare reweighting/resampling where appropriate, evaluate threshold changes cautiously, and monitor outcomes after deployment. No single method guarantees fairness.

## Limitations
- Historical census data may encode societal and measurement biases.
- Excluding sensitive fields from model inputs does not eliminate proxy bias.
- Group metrics can be unstable for small groups and can conflict with one another.
- SHAP explains model behavior relative to a baseline; it does not prove causation.
- This notebook is educational and is not intended for real-world high-impact decisions.
